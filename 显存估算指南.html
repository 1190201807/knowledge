大模型训练显存估算指南

从构成分解到快速系数法 —— 以 Qwen2.5-VL-3B LoRA 微调为例

方法一:精确构成分解

把峰值显存拆成四项,逐项估算后相加。适合理解原理、OOM 后定位瓶颈。

总显存 = 模型权重 + 训练状态(梯度+优化器) + 激活值 + CUDA开销
模型权重

参数量 × 每参数字节数

bf16 每参数 2 字节。只要模型在显存里,这部分跑不掉。
例:3.75B × 2B = 7.5 GB

训练状态(梯度+优化器)

可训练参数量 × 每参数字节数

只对可训练参数计费。LoRA 把它压缩到总参数的 ~1.3%。
例:50M × 6B ≈ 0.3 GB

激活值

∝ 单步 token 数(batch × 序列长度)× 层数

前向中间结果,反向传播要用。按“一次喂进模型的 token 量”计费,与数据集总量无关。梯度检查点把它压到 1/5~1/10;视觉模型中图片 token 数是最大变量。例:2~4 GB

CUDA 开销

内核工作区 + 显存碎片

显卡初始化与分配器预留,基本固定。例:~1 GB

每参数显存成本速查字节/参数说明
权重 bf162最常见的底座精度
权重 fp324—
权重 4bit(QLoRA)0.5底座量化
梯度 bf162仅可训练参数
优化器 8bit 动量 ×22adamw_8bit
优化器 fp32 动量 ×28标准 AdamW
fp32 master 副本4混合精度全量微调需要

全量微调(fp32 AdamW)总账 = 2 + 2 + 4 + 8 = 16 字节/参数 → 3.75B 模型 ≈ 60 GB,还没算激活值。 这就是 LoRA 的意义:把这一项从 50+ GB 压到 0.3 GB。

激活值完整公式(按 token 计费)

激活值 ≈ (batch × 序列长度) × 层数 × h × 2字节 × 份数 + logits
元素含义典型值 / 查法
batch × 序列长度单步喂进模型的总 token 量。序列长度 = 每条输入的 token 数;数据集总量与显存无关,只影响训练时长由数据形态决定
层数 LTransformer 块的个数,不是张量总数config.json 的 num_hidden_layers(3B≈36,7B≈28)
hhidden size,每个 token 的向量长度(模型的“宽度”)config.json 的 hidden_size(3B≈2048,7B≈3584)
2 字节bf16 下每个元素的字节数fp16 同为 2,fp32 为 4
份数每层每个 token 要保存几份 h 维向量:开梯度检查点 1 份(只存层输入),不开约 17 份LoRA/QLoRA 工具链默认开检查点
logits输出层对词表的打分 = 单步 token 数 × 词表 × 2字节;反向一开始就要用,检查点省不掉Qwen 词表约 15 万

心算捷径:开检查点时每 token 总价约 0.5~1 MB(含 logits),直接乘单步 token 数。例:3B 模型、5k token → 0.7 GB + logits 1.5 GB ≈ 2.2 GB,对应计算器“中”档。

方法二:快速系数法

选型阶段只需要一次乘法。层数、hidden dim 等细节在这个精度下全部被总参数量吸收。

所需显存 ≈ 参数量(B) × 系数 + 固定开销(3~6 GB)
训练方式系数(GB / 每 1B 参数)说明
LoRA(bf16 底座)~2.0权重大头,LoRA 训练状态可忽略
QLoRA(4bit 底座)~0.6底座量化到 4bit,最省
全量微调(8bit 优化器)~7权重+梯度+优化器全量存
全量微调(fp32 AdamW)~16最贵的方式

固定开销(3~6 GB)= 激活值 + CUDA 开销的打包估计,主要看单步输入的 token 总量(batch × 序列长度;视觉模型看图片分辨率折算的 token 数),与模型大小关系不大。

工程上的正确姿势

公式只用来圈候选名单(2 分钟),之后靠实测捕捉所有公式算不准的东西。

圈候选

用系数表反查,圈出 2~3 个候选模型。

试跑

保守 batch 起训,跑 20~50 步,盯 nvidia-smi 或脚本里的 max_memory_reserved。

调参

余量大就把 batch 翻倍;贴边了就加 gradient_accumulation_steps。

升档

峰值稳定后余量仍 > 30%,说明还能往上试一档模型。

能训的最大 ≠ 该选的最好

任务难度匹配:里程表读数这类感知任务 3B 微调后通常够用,提升数据质量比硬上 70B 划算。推理成本:训完要部署,70B 的 LoRA 推理需要 48GB 卡,3B 一张消费级卡就跑。

· 本页估算针对训练;纯推理的显存由权重 + KV cache 决定,是另一套公式。

· GRPO 等训练与采样共存的场景(vLLM 同卡)需叠加推理引擎占用,见课程脚本 Qwen2_5_(7B)_R1_GRPO.py 的 gpu_memory_utilization 参数。

· 所有数字为数量级估算,以实测为准。
