# 工程并发问题检查清单

> 用法：设计评审、代码评审、排查线上问题时逐项过一遍。不要靠记忆，靠清单。

## 一、高频问题分类

### 1. 非原子复合操作

- 读-改-写：`count++`、`balance += x`、`stock--`
- 检查-后-执行：先查再插、先判断再扣、懒加载
- 跨方法复合：`get` 之后 `put`、`containsKey` 之后 `remove`
- 典型症状：少加、超卖、重复创建、状态丢失

### 2. 可见性与安全发布

- 停止标志/配置开关不是 volatile
- 构造未完成的对象逸出（构造函数里启动线程、注册监听器）
- 懒加载单例、DCL 缺少 volatile
- 典型症状：debug 正常、release 出错；偶发卡死

### 3. 共享了不该共享的对象

- SimpleDateFormat、HashMap/ArrayList、StringBuilder、Random
- 非线程安全的第三方 client、JDBC Connection、工具类
- static 可变字段、单例里的可变成员
- 典型症状：数据串号、偶发异常、结果错乱

### 4. 线程上下文

- ThreadLocal 在线程池中未清理，导致用户/租户/traceId 串号
- 异步切换线程后 MDC、事务、安全上下文丢失
- 典型症状：日志 traceId 对不上、A 用户看到 B 用户数据、异步操作不在事务里

### 5. 死锁与活性

- 多把锁顺序不一致
- 持锁调用回调/RPC/发消息，对方又回调回来
- 线程池饥饿死锁：父任务占满线程等子任务
- wait 不在 while 循环、notify 早于 wait
- 典型症状：线程 dump 中 BLOCKED/WAITING 堆积，接口整体超时

### 6. 线程池与异步

- 无界队列导致任务堆积/OOM
- 所有业务共用一个池，慢任务拖垮全局
- submit 不取 Future，异常静默丢失
- 定时任务抛异常后停止后续调度
- 吞掉 InterruptedException、不响应取消
- 关闭时不 shutdown，任务丢失或进程不退出
- 典型症状：任务不执行、内存上涨、应用停不下来

### 7. 生命周期与资源

- 对象已销毁/回调未注销，仍有线程在访问
- 线程泄漏、连接池借还不配对
- 异常路径漏解锁；C++ 忘记 join/detach 导致 terminate
- 典型症状：句柄泄漏、use-after-free、NPE

### 8. 只在生产暴露

- 编译器优化、内存序、CPU 核数差异
- 压测不足，低概率交错才触发
- 并发 + 重试 + 超时叠加放大
- 典型症状：测试环境稳定，线上偶发

## 二、设计评审：并发十问

> 速查版。每问的详细解释、检查动作和"我的理解"空白见 [并发十问](并发十问.md)。

1. **所有权**：这块可变状态归谁？能不能不共享（不可变、线程封闭、消息传递）？
2. **不变量**：并发下必须永远成立的业务规则是哪几条（库存≥0、余额≥0、状态不可回退）？
3. **原子边界**：哪些操作是读-改-写或检查-后-执行？原子性要覆盖到哪一步？
4. **同步手段**：锁、原子类、CAS、数据库条件更新/唯一约束，选哪个？为什么？
5. **锁纪律**：有几把锁？固定顺序是什么？持锁期间会不会调用外部代码、IO、回调？
6. **等待与超时**：所有阻塞是否可超时、可取消？唤醒条件是否在循环里检查？
7. **执行边界**：任务进哪个池？队列有界吗？拒绝策略是什么？会不会池内等池？
8. **上下文与生命周期**：ThreadLocal/traceId/事务怎么传播和清理？关闭时在途任务怎么办？
9. **顺序与幂等**：同一实体的事件会乱序或重复吗？重试安全吗？
10. **可观测性**：出问题时看哪些指标能定位（线程数、队列深度、拒绝次数、锁等待）？

## 三、代码评审气味清单

- [ ] 非 final 的 static 可变字段
- [ ] 共享 Map/List 没有用并发容器，却有多线程读写
- [ ] 先查询后修改/插入，中间没有原子保证
- [ ] 共享变量上出现 `++`、`--`、`+=`
- [ ] SimpleDateFormat/Calendar/Random 作为成员变量
- [ ] 锁对象是 String、Integer、this，或 this 与 class 混用
- [ ] 持锁调用 RPC、DB、发消息、回调
- [ ] wait 不在 while 循环；只用 notify 不用 notifyAll
- [ ] catch InterruptedException 后不恢复中断
- [ ] ThreadLocal 没有 remove
- [ ] 线程池用无界队列；submit 不处理 Future
- [ ] 每次请求 new Thread 或自建线程池
- [ ] 单例懒加载无同步，或 DCL 无 volatile
- [ ] 测试里用 Thread.sleep 等并发结果

## 四、场景速查

| 场景 | 常见错误写法 | 正确做法 |
|---|---|---|
| 计数器/指标 | `count++` | `AtomicLong` / `LongAdder` |
| 库存/余额扣减 | 先查后扣 | 条件更新 `UPDATE ... WHERE stock >= n`；乐观锁 |
| 防重复创建 | 先查再插 | 唯一索引兜底 + 捕获冲突 |
| 本地缓存 | HashMap 的 get/put | `ConcurrentHashMap.computeIfAbsent`（函数内不做耗时操作） |
| 懒加载单例 | DCL 无 volatile | 静态内部类 / volatile DCL |
| 日期格式化 | 共享 SimpleDateFormat | DateTimeFormatter（不可变）或每次新建 |
| 线程池 | 无界队列、全局一个池 | 有界队列 + 业务隔离 + 明确拒绝策略 |
| 停止线程 | 轮询非 volatile 标志 | volatile 标志 + interrupt + awaitTermination |
| 请求上下文 | ThreadLocal 直接进池 | 任务包装传播上下文 + finally remove |
| 优雅停机 | 没有 shutdown 流程 | 停收新任务 → 等待在途 → 超时强停 |

## 五、让机制替你记

1. **架构上收敛**：绝大多数业务代码按单线程写，并发只出现在少数"并发边界"（仓储、调度器、消息消费者、缓存层）。需要审查的面从全代码缩到几个类。
2. **显式标注**：`@ThreadSafe`、`@NotThreadSafe`、`@GuardedBy("lock")`；C++ 用 Clang 的 `GUARDED_BY`/`REQUIRES` 注解，让编译器检查。
3. **工具进 CI**：C/C++/Go 跑 TSan/race detector；Java 跑 jcstress/Lincheck；静态分析开 Error Prone/SpotBugs 的并发规则。
4. **运行时监控**：线程数、池队列长度、拒绝次数、任务耗时、锁等待时间，全部打点和告警。

## 六、经验法则

- 能不共享就不共享；要共享优先不可变；必须共享可变就封装到一个组件里。
- 一切等待都有超时，一切异步都有边界（池、队列、关闭策略）。
- 每个共享变量只有一个"写者模块"，其他模块只能读或发消息。
- 先保证正确，再优化性能；优化必须有压测数据。
- 并发 bug 靠工具和压测抓，不靠肉眼 review。
