**目标**：会用锁和条件变量，能写出正确的并发组件。

### 要回答的问题

### 核心内容

## 阶段 3：内存模型

> 讲义：[阶段 3 讲义](阶段3-讲义.md)

**目标**：理解 happens-before，能解释所有"玄学"并发 bug。

### 要回答的问题

- 为什么需要内存模型？编译器和 CPU 会做什么重排？
- happens-before 有哪些规则？如何推导一段代码的可见性？
- Java 的 volatile 和 C++ 的 volatile 有什么区别？
- DCL 单例为什么需要 volatile？final 字段有什么保证？

### 核心内容

1. 问题来源：重排与缓存
2. happens-before：程序顺序、锁释放/获取、volatile/原子读写、线程 start/join、传递性
3. 内存序：顺序一致性、acquire/release、relaxed、内存屏障
4. 安全发布：final 字段、this 逸出、发布逃逸、DCL
5. 跨语言差异：
   - Java：volatile 提供可见性 + 顺序保证
   - C++：volatile 不用于线程同步，必须用 std::atomic
   - Go：sync/atomic、channel 的 happens-before
   - Rust：Send/Sync 在编译期约束

### 动手实验

- [ ] 用 volatile 修复可见性循环，解释原理
- [ ] DCL 单例：错误版 → volatile 修正 → jcstress 验证
- [ ] 基于 acquire/release 实现"初始化一次并安全发布"
- [ ] 写几个 litmus test 风格的小程序

### 过关标准

- [ ] 能画出任意代码段的 happens-before 图
- [ ] 能解释 DCL、final、安全发布
- [ ] 能说清 volatile 在 Java 和 C++ 中的语义差别

## 阶段 4：并发模式与高层抽象

> 讲义：[阶段 4 讲义](阶段4-讲义.md)

**目标**：从"正确"走向"好用、易维护"。

### 要回答的问题

- 什么场景该用锁、原子类、消息传递、不可变对象？
- 线程池参数怎么定？队列为什么必须有界？
- 如何保证同一实体的事件顺序？
- actor/CSP 相比共享内存解决了什么问题？

### 核心内容

1. 任务抽象：Future/Promise、CompletableFuture、async/await、结构化并发
2. 线程池：核心参数、队列选择、拒绝策略、线程数估算、任务粒度、业务隔离
3. 并发数据结构：ConcurrentHashMap、跳表、COW、读写锁、无锁队列、LongAdder
4. 并发模式：生产者-消费者、work stealing、reactor、actor、CSP/channel、event loop、不可变快照
5. 设计原则：优先不共享、最小化可变状态、消息传递、并发边界收敛

### 动手实验

- [ ] 用阻塞队列实现任务调度器（关闭、限流、异常处理）

- [ ] 读 ConcurrentHashMap 或 sync.Map 的实现思路并写笔记

## 阶段 5：诊断、验证与性能

**目标**：能独立排查并发问题，并用数据说话。

### 要回答的问题

- 线上接口整体变慢/卡住，如何判断是不是并发问题？
- 如何用 TSan/race detector 定位数据竞争？
- 锁竞争和伪共享如何量化？
- 如何写出可重复的并发测试？

### 核心内容

1. 动态检测：ThreadSanitizer、Go race detector、Valgrind helgrind、jcstress、Lincheck
2. 死锁与卡顿排查：jstack/线程 dump、pstack、gdb、perf、async-profiler
3. 性能分析：锁竞争、伪共享（缓存行 64B）、上下文切换、NUMA、锁粗化/细化
4. 测试策略：压力测试、故障注入、可重复交错、CI 集成

**目标**：理解工业级实现，必要时能自己写高性能并发组件。

### 核心内容

1. 无锁基础：CAS、ABA、内存序精调、hazard pointer、epoch、RCU
2. 工业级实现：无锁队列/栈、Disruptor ring buffer、ConcurrentHashMap、AQS、sync.Mutex
3. 语言运行时：JVM JIT 与 JMM、Go 调度器、Rust Send/Sync
4. 进阶理论：线性一致性、共识问题、The Art of Multiprocessor Programming
