# 阶段 4 阅读路线：三遍读法

> 配套文档：[阶段4-讲义.md](./阶段4-讲义.md)
> 适用：概念优先、代码作示例的读法。讲义每节本来就是"先概念、后代码"，所以第一遍可以放心跳过所有代码块，不影响连贯。
> 为什么不按讲义原文顺序读：讲义按"任务抽象 → 执行资源 → 状态边界"三条主线组织，作为参考手册没问题；但前三章（§2–4）是 Java API 密度最高的部分，直接顺着读容易在代码里劝退。这份路线把最依赖 API 的 §3/§4 挪到第二遍。

---

## 第一遍 · 概念主线（跳过所有代码块，只读文字、表格、图）

1. **§1 这一阶段在解决什么** — 全读。三条主线（任务抽象 / 执行资源 / 状态边界）是整份讲义的地图。
2. **§2 只读 2.1 的"六个问题"清单 + 2.2 开头的 Future/Promise 定义** — 知道"任务和执行要分开"就够了，代码和跨语言对照表先跳过。
3. **§5 线程池：七个参数与执行顺序** — 全读。这是本阶段的地基；5.3 那张执行顺序图值得自己画一遍。
4. **§6 线程数与队列容量怎么定** — 全读。公式看懂直觉即可：IO 密集 ≈ 核数 × (1 + 等待/计算)。
5. **§7 拒绝策略、隔离、关闭与可观测性** — 全读，纯概念。
6. **§9.2 组合陷阱** — 本阶段最重要的概念：**线程安全的组件组合起来不一定线程安全**。六个例子都只有几行，当反例示意图看。
7. **§10.1 生产者-消费者 + §10.3 模式速览表** — 跳过 10.2 work stealing 的 ForkJoin 代码。
8. **§11 reactor 与 event loop** — 全读。
9. **§12 actor 与 CSP** — 读文字和 12.4 对比表；12.2/12.3 的两段代码本来就很接近伪代码，当示意图看。
10. **§13 顺序、幂等与单一写者** — 全读。这是把前面所有模式串起来的思想核心。
11. **§14 选型与设计原则** — 决策树 + 12 条原则。
12. **§18 小结** — 用那 10 句话自检第一遍有没有读明白。

第一遍读完应该能回答：

- 阶段 4 和阶段 2–3 的分工是什么？（把锁用对 → 少用共享内存，把并发收敛到少数边界）
- 线程池的执行顺序为什么"无界队列会让 maximumPoolSize 失效"？
- 为什么队列必须有界？
- "单方法原子 ≠ 组合原子"是什么意思？能举一个反例吗？
- actor / channel 和共享内存 + 锁相比，交换了什么代价？

## 第二遍 · Java 异步工具（这次带着代码读）

- **§3 CompletableFuture**：按 3.1 为什么需要组合 → 3.2 组合子表 → 3.3 示例逐行对照注释的顺序读。重点理解 3.3 下面那几条"逐条语义"（`allOf` 失败不取消其他任务、`orTimeout` 只改结果不停任务、`join()` 什么时候会阻塞）。
- **§4 结构化并发与虚拟线程**：对比 §3 的"任务逃逸"问题，看 `StructuredTaskScope` 怎么用作用域解决它。
- **§2.3 取消与超时**：有了线程池和异步的上下文，"设计任务先回答五个问题"就好回答了。
- **§10.2 work stealing**：现在可以读 ForkJoin 的分治求和代码了，对照 §5 的线程池思考"它为什么不适合阻塞 IO"。

第二遍读完应该能回答：

- `thenApply` 和 `thenApplyAsync` 的区别？默认用哪个池？为什么生产代码要显式传 executor？
- `allOf` 某个任务失败时，其他任务会停吗？怎么才能真正取消？
- 虚拟线程让什么变便宜了？没让什么变强？为什么不要池化它？

## 第三遍 · 数据结构细节 + 动手

- **§8 并发容器**：先读 8.1 的三条铁律；8.2 ConcurrentHashMap 精读（结构、原子复合 API、坑）；8.3–8.8 按需查，不必一次读完。
- **§9.1 无锁队列**：读"难点"清单（ABA、内存回收、伪共享）和结论（不要自己写）即可，细节留给阶段 6。
- **§15 四个实验**：动手做，实验记录表填进讲义。
- **§16 常见误区**：当 checklist 用，每条对照讲义找出处。
- **§17 自测四问**：先不看讲义自己写答案；然后回对话里让我按这四问提问。
