1. unsloth 是什么

unsloth 是一个专门加速大模型微调（训练）的开源库。它的卖点不是「功能」，而是「快 + 省显存」。

它解决了什么

  • 最快 2-5 倍 训练速度提升
  • 省约 70% 显存占用（可下放到消费级显卡微调 LLaMA/Qwen 等 7B~13B）
  • 4bit / 8bit 量化（QLoRA）开箱即用

三大核心手段

  • TRITON 手写优化算子：重新实现 LoRA 底层矩阵运算，砍掉浪费的计算。
  • 更省显存的前/反向传播：复用中间结果，压低峰值显存。
  • 无缝结合 QLoRA：把模型压成 4bit，让小卡也能微调大模型。
注意：unsloth 不是 DeepSpeed / 分布式多卡框架，它主要在单卡优化上做文章。超大模型多卡训练时，还会额外配 DeepSpeed。

2. vLLM 是什么

vLLM 是一个纯推理引擎，只做生成/推理，不做训练。它追求高吞吐、低显存，常用于生产部署。

  • Continuous batching（连续批处理）：边生成边插入新请求，吞吐更高。
  • PagedAttention：像操作系统分页一样管理 KV Cache，显存不浪费。

一句话：负责「模型进来 → 输出出去」跑得快又省内存。

3. 二者的关系

很多初学者以为「vLLM 管推理、unsloth 管训练」，大致方向对，但有一处修正：

微调阶段（unsloth 自己） ────▶ 推理验证阶段（借用 vLLM）
  • 训练时：unsloth 用自己的优化算子做 LoRA/GRPO 训练，此时 vLLM 基本闲置，只预占一块显存当引擎。
  • 推理时：fast_inference=True 让 unsloth 在内部起一个 vLLM 引擎当推理后端，fast_generate 无缝对接。
常用路径一（生产）
训练完 → model.inference(model) 转原生权重 → 用 vLLM / llama.cpp 独立部署。
常用路径二（就地验证）
训练完 → fast_inference=True 直接调 fast_generate 快速验证效果。
什么是「转原生权重」？训练结束时的模型不是完整模型：基座权重被冻结且可能压成 4bit，LoRA 只是挂在外面的小补丁（几十 MB 的 adapter_model.safetensors）——这是 unsloth/PEFT 的训练态格式，vLLM / llama.cpp 读不了。「转原生」就是把它还原成标准完整模型，分三步：
  • 合并（merge）：把 LoRA 的增量数学上加回基座（W = W₀ + B·A），从此不再有「补丁」，就是一套普普通通的完整权重。
  • 反量化/升精度：把 4bit 权重解压回标准的 fp16 / bf16。
  • 按标准格式落盘：存成和官方 Qwen 发布包一模一样的目录结构（config.json + *.safetensors + tokenizer 文件）。
转完之后，vLLM 才能 vllm serve 直接加载，llama.cpp 也能再转 GGUF 使用。

4. 为什么快的地方不同：训练 vs 推理的工作负载

第 3 节只说了「一个训练快、一个推理快」，但没解释为什么快的地方不同——根源在于训练和推理的工作负载完全不一样。

4.1 训练和推理是两种不同的计算

训练（微调）推理（生成）
前向传播✅ 要✅ 要
反向传播（算梯度）✅ 要（最重的部分）❌ 不要
优化器更新权重✅ 要❌ 不要
逐 token 循环生成❌ 一次处理整个序列✅ 一个 token 一个 token 蹦
典型场景单任务、吃满一张卡同时服务几十上百个请求

4.2 unsloth 为什么快：优化「反向传播」这条链路

训练的瓶颈是：前向算一遍 → 反向再算一遍梯度 → 优化器更新。反向传播的计算量约是前向的 2 倍，而且要保存大量中间激活值，显存经常爆。unsloth 的三板斧全是冲着这条链路去的：

  • TRITON 手写算子——把 LoRA 的矩阵乘等底层运算重写，减少冗余读写。反向传播也要经过这些算子，所以省的是「每一步都省」。
  • 复用中间结果——前向算完的东西不扔，反向直接用，既省显存又省重复计算。
  • QLoRA（4bit）——冻结的大模型权重压成 4bit 存，只有小 LoRA 参数参与梯度计算。
关键点：这些优化都依赖「有反向传播、能精确控显存」这个训练特有场景。而且训练时通常一次只跑一个任务，把单条链路榨干就够了。

4.3 vLLM 为什么快：优化「并发调度」这件事

推理没有反向传播，计算本身不重，它的瓶颈在别处：

  • 解码是显存带宽瓶颈——每生成一个 token，都要把整个模型权重读一遍。batch=1 时 GPU 算力大量闲置（权重读完了，但只算了一个人的一份）。
  • 所以核心手段是「同时服务更多人」：
    • Continuous batching：不等一整批生成完，谁结束就立刻塞新请求进来，GPU 始终吃饱 → 吞吐量暴涨。
    • PagedAttention：每个请求的 KV Cache 长短不一，传统方式按最长预留显存浪费严重；vLLM 像操作系统分页内存一样按需分配碎片。
关键点：vLLM 的优化是调度和内存管理层面的，针对「多请求、流式、KV Cache」这种服务场景——这些在训练里根本不存在。

4.4 一张图总结

训练链路: 前向 → 反向 → 优化器 ← unsloth 在这条路上做算子级优化
            (单任务，重计算重显存)

推理链路: 请求队列 → 批处理调度 → 逐token生成 → KV Cache管理
                              ← vLLM 在这条路上做调度级优化
呼应第 3 节：这也解释了 GRPO 训练中 unsloth 可以借用 vLLM 来生成采样文本（强化学习需要模型自己生成 rollout），因为「生成」这部分恰好是 vLLM 的主场——但梯度更新仍然走 unsloth 自己的算子。两者不是竞争关系，而是各管一段流水线。

5. 不用 unsloth：纯 HF + PEFT 微调

「HF + PEFT」是标准基线：Transformers 负责加载模型与训练循环，PEFT 负责把完整权重换成可训练的 LoRA 小参数集。这样完全不需要 unsloth。

完整可运行示例（文本 SFT）

import torch
from transformers import (
    AutoTokenizer, AutoModelForCausalLM, TrainingArguments,
    Trainer, DataCollatorForLanguageModeling,
)
from peft import LoraConfig, get_peft_model
from datasets import load_dataset

# 1. 加载 tokenizer + base 模型
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-7B-Instruct")
model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-7B-Instruct",
    torch_dtype=torch.bfloat16,
    device_map="auto",
)

# 2. 一键切成 LoRA 版本（冻结原参数，只训小参数量）
lora_config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                    "gate_proj", "up_proj", "down_proj"],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
)
model = get_peft_model(model, lora_config)

# 3. 构造并格式化数据集
dataset = load_dataset("json", data_files="train.jsonl")

def format_fn(examples):
    texts = [t + tokenizer.eos_token for t in examples["text"]]
    return tokenizer(texts, padding="max_length",
                     truncation=True, max_length=512)

dataset = dataset.map(format_fn, batched=True)

# 4. 用普通 Trainer 训练
training_args = TrainingArguments(
    output_dir="./lora_out",
    per_device_train_batch_size=1,
    gradient_accumulation_steps=8,
    learning_rate=2e-4,
    num_train_epochs=3,
    bf16=True,
    logging_steps=10,
    save_strategy="epoch",
)

trainer = Trainer(
    model=model,
    args=training_args,
    tokenizer=tokenizer,
    train_dataset=dataset["train"],
    data_collator=DataCollatorForLanguageModeling(tokenizer, mlm=False),
)
trainer.train()

# 5. 保存 LoRA 适配器
model.save_pretrained("./lora_final")
tokenizer.save_pretrained("./lora_final")

流程小结

  • Transformers：AutoTokenizer + AutoModelForCausalLM 加载模型。
  • PEFT：LoraConfig + get_peft_model 套 LoRA。
  • Trainer：跑训练循环，自动处理梯度、checkpoint。
提示：若显存不够，可把 AutoModelForCausalLM.from_pretrained 此行配对 load_in_4bit=True（from transformers 原生、或 bitsandbytes），实现 QLoRA。

6. unsloth 版 ↔ HF+PEFT 版 逐行对照

你那份 Qwen GRPO 脚本里的几行，其实就是上面 HF 流程的「换皮版」：

unsloth 版HF + PEFT 版说明
FastLanguageModelAutoModelForCausalLMunsloth 顺带打包了 4bit 量化、vLLM 等
FastLanguageModel.from_pretrained(...)AutoModelForCausalLM.from_pretrained(...)加载基座模型
FastLanguageModel.get_peft_model(...)get_peft_model(...) + LoraConfig加 LoRA
GRPOTrainerTrainer / SFTTrainer训练循环（GRPO 是强化学习专用 Trainer）
结论：概念没变——HF 管加载和训练循环，PEFT 管 LoRA。unsloth 只是同一套骨架的「加速版」，把底层算子换成省显存的手写优化版，其余流程照旧。

7. 多模态场景的特殊说明（Qwen-VL）

你那份 qwen_vl_car_insurance_train.py 之所以不能用 fast_generate，而只能用 model.generate，原因有二：

  1. 加载时没开 fast_inference=True —— 它用的是 FastVisionModel.from_pretrained(...)，未启用 vLLM 后端，所以走 HF 原生 generate。
  2. 多模态不适合 vLLM fast 接口 —— 图片必须先由视觉编码器算成向量、再按位置拼进序列，vLLM 对「输入里混图片」的支持不完整，unsloth 对视觉模型干脆退回 HF 原生接口。

所以多模态手动准备输入：

inputs = tokenizer(test_image, input_text, add_special_tokens=False,
                   return_tensors="pt").to("cuda")
_ = model.generate(**inputs, streamer=text_streamer, max_new_tokens=128,
                   use_cache=True, temperature=1.5, min_p=0.1)

而纯文本 + fast_inference=True 时，tokenize 被 vLLM 内部包办，直接给字符串即可：

output = model.fast_generate(
    text,                          # 裸字符串，内部自动 tokenize
    sampling_params=sampling_params,
    lora_request=model.load_lora("grpo_saved_lora"),
)[0].outputs[0].text

8. 一句话总结

  • vLLM = 推理引擎；unsloth = 训练加速库。
  • unsloth 微调用自己的算子，推理时把 vLLM 当高吞吐后端（fast_inference=True）。
  • 不依赖 unsloth 也能微调：Transformers 加载 + PEFT 套 LoRA + Trainer 训练，就是上文的 HF+PEFT 基线。
  • 多模态（视觉）模型走 model.generate 手动 tokenize；纯文本可走 vLLM 的 fast_generate。
