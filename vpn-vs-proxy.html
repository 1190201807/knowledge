代理 vs VPN:一个报文的两种旅行方式

核心分野只有一句话:代理是"终结 + 中继"——传输层连接在代理处被腰斩成两条, 原始网络报文从未存在;VPN 是"封装 + 路由"——原始 IP 包作为整体被加密、 塞进新壳,穿越隧道后原样复活,由内核像路由器一样转发出去。

IP 头 TCP 头 应用层载荷 加密区 被改写/新生成

关键:从应用发出的第一个包起,src=198.51.100.5, dst=192.0.2.10 就再没变过—— 指向真实服务器的网络包(dst=93.184.216.34)在你这边从未存在; 真实目标只以域名 example.com 的形式写在第一条应用层消息里,由代理解析后自行建连。 对比场景二:VPN 图里内层 src/dst 一路可追,代理图里"内层"根本不存在。

"转发时刻"代理到底做了什么? 每一批字节到达后,代理进程都要做一次 recv()(从一条连接的内核缓冲区读入自己的用户态缓冲区)加一次 write()(写入另一条连接的发送缓冲区)——这是字节级的"存储-转发", 内容零处理(密文它也读不懂),但有两个真实后果:
① 反压逐跳传导:若应用读得慢,代理→应用方向的缓冲区先填满,代理暂停从服务器读取, 服务器那边 TCP 窗口收缩、发送放缓——慢会沿着链条往回传。
② 对比明文模式:以上是 CONNECT 隧道模式;若走明文 HTTP 代理(请求行带绝对 URL), 代理是真正解析内容的——它能看到并改写一切(缓存、过滤、增删头部), 这也是企业网关做内容审计、以及"HTTPS 中间人"需要你信任它伪造证书的原因。

2. 网络层视角:两段报文,头都是"生来如此"

第一段(你 → 代理) —— 目的地址从一开始就是代理,没有任何设备改写过它:
IP 头源=你的IP → 目的=代理IP
TCP 头你的随机端口 → 8080
应用层消息CONNECT example.com:443 … 之后是 TLS 密文

包到达代理后,外层 IP 头 / TCP 头在代理的内核协议栈里被正常"消费"并丢弃, 代理进程通过 recv() 拿到的只是纯应用层字节—— 代理从头到尾没有"拆开网络层报文"这个动作,因为报文头根本没被交到它手里。

第二段(代理 → 目标服务器) —— 头由代理的内核为这条全新连接从头生成:
IP 头(全新)源=代理IP → 目标真实IP
TCP 头(全新)代理新端口 → 443,新序列号
同一批应用层字节原样照抄(代理不解密、不理解)
网络层的"修改"发生在哪? 严格说,没有任何设备改写过网络层报文。 第二段的头不是"改"出来的,是代理内核为一条全新连接生成的。 真正被终结的是传输层(TCP 连接腰斩成两段);端到端存活的只剩应用层会话(如 TLS)。 目标服务器看到的 TCP 对端是代理自己。

图中记法约定:src=…, dst=… 表示报文的源/目的地址;"A → B" 仅表示一次地址改写(NAT), 如 src 10.0.0.2 → VPN服务器IP。这样一眼可查:全程 src/dst 被改写的只有两处, 都是 NAT 干的(去程改源、回程改目的),且互为精确逆操作;隧道封装从不改写内层地址。

2. 网络层视角:封装而非改写

线上传输的报文(你 → VPN 服务器) —— 原始包整体成为加密载荷,原封不动:
外层 IP 头你 → VPN服务器
UDP如 51820
加密载荷(整个原始 IP 包,含头,一字节不动)
内层 IP 头10.0.0.2 → 真实服务器
TCP 头你的端口 → 443(端到端活着)
应用数据

VPN 服务器解密后,把完好的原始包经 TUN 还给内核。多数场景下内核顺手做一步 SNAT(这才是真正意义上"改写网络层报文"的操作,由 netfilter/conntrack 完成, 而非隧道本身):

NAT 之后发往目标服务器的报文 —— 只有源地址被翻译,其余原样:
内层 IP 头源被 NAT:10.0.0.2 → VPN公网IP:33333,目的不变
TCP 头原样保留(仅端口随 NAT 映射)
应用数据原样保留
回程不需要任何人"指挥"。 目标服务器只是把源/目的对调,发回"它以为的客户端"(VPN 服务器); VPN 服务器内核凭 conntrack 记忆把目的地址翻译回 10.0.0.2,路由表把它赶进 TUN, VPN 进程重新封装后发还给你。企业内网场景可能不做 NAT:内网路由器都认得 10.0.0.0/24 该往 VPN 服务器送,此时源 IP 全程保留,客户端在隧道内有自己的身份 IP。

总账

代理VPN
角色应用层端点(终结 + 中继)三层路由器(封装 + 路由)
"原始报文"的命运从未存在过作为整体穿越隧道,原样保留
谁决定报文去向应用自己(读配置后 connect 到代理)内核路由表(应用无感知)
网络层报文是否被改写没有;第二段的头是全新生成的隧道不改写;NAT 仅翻译源地址

目标服务器的 TCP 对端代理自己你(经 NAT 显示为 VPN 的 IP)
不配合的程序绕过代理、流量泄露照样被 TUN 接管
